# 마실(채움지도) — Pleos Connect 차량용 여행 기록 앱 (서울·대전·부산 시범판)

> 룰렛으로 떠나는 우리 땅 여행. 시·군·구를 랜덤으로 뽑아 떠나고, 가는 길엔 지역 이야기를 오디오로 듣고, 도착하면 지도 한 칸이 채워지는 Pleos Connect 차량용 앱.
>
> 2차 기획(12/3 PT) 컨셉: **"P도 J처럼, 운전이 아니라 여행의 한 장면으로."** 계획 없이 타도 앱이 테마·코스를 골라 주고, 다녀온 곳은 추억처럼 쌓입니다. → [6. 2차 기획](#6-2차-기획-123-pt)

- 앱 이름: **마실** (런처 표시 이름). 코드·패키지·문서 안의 이름은 아직 "채움지도"를 그대로 씁니다.

## 프로토타입 범위

- 지도는 **전국 시·군·구 230곳을 그대로** 보여 줍니다.
- **시범 지역만 활성화**: 서울특별시 25개 구 + 부산광역시 16개 구·군 + 대전광역시 5개 구 = **46칸**
  - 시범 지역: **흰색**, 누르면 여행지로 선택, 룰렛 후보
  - 그 외 지역: **회색**, 눌러도 반응 없음, 룰렛 후보에서 제외
  - 다녀온 시범 지역: 초록색 (사진 채우기는 1번 TODO) / 지금 고른 여행지: 주황색
- 설정은 `core/model/PilotScope.kt` 한 곳에 있습니다. 전국으로 넓힐 때는 `ACTIVE_SIDO`만 바꾸면 됩니다.

현재 상태: 룰렛 → 출발 → 오디오 스토리 → 도착 → 주차 → 지도 채우기까지 1차 흐름이 끝까지 연결돼 있고, 그 위에 2차 기획의 **상단 메뉴 5탭·설정(켜기·끄기)·내 지도·여행 기록**이 들어가 있습니다. 남은 할 일은 코드 안에 `TODO(n번)`으로 표시돼 있습니다.

## 1. 실행 방법

| 화면 | 2560×1440px, 160dpi(mdpi), 12.8인치 |

| 빌드 | JDK 17, Android SDK Platform 34, Build-Tools 34.0.0, Gradle 8.9(래퍼) |

### APK
- 위치: `apk/` 폴더 (`팀명_채움지도_release.apk`, 실행 가능한 release 빌드)
- 설치: `adb install -r apk/<파일명>.apk` → Pleos 앱 라이브러리에서 **마실** 실행

### 소스로 실행
1. Pleos Playground 가이드대로 Pleos Connect v2.1.0 에뮬레이터 준비(Android Studio SDK Update Sites에 Pleos 시스템 이미지 등록 → AVD 생성)
2. Android Studio에서 이 폴더를 열고 Gradle Sync. Pleos SDK 저장소는 `settings.gradle.kts`에 이미 들어 있습니다.
3. `app` 실행 (또는 `./gradlew :app:assembleDebug`)
   - Pleos 에뮬레이터(Pleos 차량 서비스 있음) → 실제 SDK로 동작(경로 요청은 시스템 Pleos 내비로 전달)
   - 그 외 AAOS 에뮬레이터 → 자동으로 **Mock** 동작. `[Mock]` 패널에서 기어 P/D, 배터리 20%/100%, 여행 완료를 조작
   - 강제 전환: `app/build.gradle.kts`의 `CAR_BACKEND`를 `"mock"` 또는 `"pleos"`로
4. 단위 테스트: `./gradlew test` (시범 지역·룰렛·스토리 트리거·구·군 이름 배치·주행가능거리·칸 표시 26개)
5. Virtual Console(기어·차량 상태 조작): `adb forward tcp:8088 tcp:8088` → `http://127.0.0.1:8088/`
6. 캡처용 실행(Mock 패널 숨김): `adb shell am start -n com.team.travelmap/.MainActivity --ez hide_debug true`

### 시연 흐름 (Pleos 에뮬레이터에서 확인됨)
대전 확대 → 유성구(지도 면 또는 이름) 선택 → 대전엑스포과학공원 목적지 → 음식점 필터 → 경유지 2곳 → 출발(Pleos 내비가 경유지 포함 경로 계산·안내) → Virtual Console 에서 기어 D → 지도·장소 선택 잠금 → P 로 정차하면 다시 조작

### Mock 시연 시나리오 (서울 시청 출발)
| 배터리 | "지금 갈 수 있는 곳만" 후보 |

## 3. 공통 약속 (바꿀 때는 팀 전체 공유)

1. **지역 ID = 행정구역 5자리 코드** (`RegionId`, 예: `11680` 서울 강남구). 앞 2자리가 시·도 코드(서울 11, 부산 26, 대전 30)입니다.
2. **활성 여부는 `PilotScope.isActive(id)` 하나로 판단**합니다. 지도 색·터치, 룰렛 후보, 달성률이 모두 이것을 씁니다.
3. **좌표는 항상 (위도, 경도) 순서** (`GeoPoint(latitude, longitude)`). NaviHelper 3.0.5와 같은 순서이고, JSON 데이터도 `[위도, 경도]`입니다.
4. **차량·내비는 인터페이스만 사용**: `VehicleRepository`, `NaviRepository`. Pleos SDK를 직접 import 하는 곳은 `vehicle/Pleos*`, `navi/Pleos*` 두 파일뿐입니다.
5. **여행 흐름은 `TripCoordinator.state` 하나**: `Idle → Planned → Guiding → Arrived → Completed`
6. **주행 중 UI 제한**: `DrivingRestrictions.restricted == true`이면 리스트 상세·사진 등록·텍스트 입력을 숨기고 큰 버튼만 남깁니다.

### 큐레이션 데이터 규칙 (`assets/curation.json`)
- 키 `"11"`·`"30"`·`"26"`(도시 코드): 그 도시 어느 구가 뽑혀도 리스트에 나오는 **추천 장소 = 경유지 후보**
- 키 5자리(구 코드): 그 구 전용 장소. 구가 뽑히면 **첫 명소가 목적지**, 없으면 구 대표 지점이 목적지
- 도시 추천 장소를 목적지로 쓰지 않는 이유: 뽑힌 구와 실제 도착지가 달라지면 도착 인증이 어긋납니다.

### Git 운영
- `main`(제출용) ← `develop`(통합) ← `feature/<담당>-<기능>` (예: `feature/1-city-zoom`)
- 매일 저녁 `develop`에 병합 (병합 담당: 2번)
- 제출 시 `apk/팀명_앱이름_release.apk`를 넣고 `main`에 올립니다.

> 지금 기능(룰렛·도시 확대·큐레이션·오디오 스토리·도착 인증·주행가능거리)은 그대로 두고 그 위에 더합니다. 기획안 전문은 팀 공유 문서「채움지도 2차 기획안 — 낭만 여행 확장」에 있습니다.

### 컨셉
- **P도 J처럼**: 계획 없이 차에 타도 몇 가지만 답하면 테마와 코스를 골라 줍니다.
- **운전이 아니라 여행의 한 장면으로**: 가는 길엔 옆자리 동행처럼 주변 이야기를, 도착하면 추억처럼 지도가 채워집니다.
- **분위기**: 앱 전체를 추억·낭만 톤으로(색·글꼴·움직임). 별도 엔딩 화면은 만들지 않습니다. 디자인은 Codex 시안 기준.
- **불편할 수 있는 자동 동작은 전부 설정에서 켜기·끄기**할 수 있습니다.

### 기능
| 기능 | 설명 | 상태 |
|---|---|---|
| 시작 질문 | 누구랑·얼마나·어디까지(주행가능거리 반영). 끄면 질문 없이 기본값으로 추천 | 준비 중 |
| 테마 추천 | 6개 테마, 사진 카드, TourAPI 축제·행사·관광지 사진 | 뼈대 |
| 테마 코스 | 서로 다른 코스 3~5개(갈 곳이 적은 지역 3개, 많은 지역 최대 5개) 중 하나를 고름. 코스마다 장소 여러 곳, 최적 동선. 고른 코스에서 마음에 든 곳만 남기고 나머지 다시 추천 → [코스 기준](#코스-기준-이슈-9) | 준비 중 |
| 가는 길 추천 | 목적지 가는 경로 위 도시의 추천 코스(예: 서울→부산이면 대전). 국도 위주, 고속도로는 IC 3km 안만, 걸리는 시간과 함께 | 준비 중 |
| 랜덤 다트 | 작은 아이콘. 누르면 바로 여행지를 골라 줌(자동으로 던지지 않음) | 준비 중 |
| 주행 중 동행 | 내비 옆 화면에 지나는 곳 카드, 음성 해설, 위치 이야기 자동 재생 | 동작 (지나는 곳 카드: 관광지는 한 줄 소개 후 "잠깐 들렀다 갈까요?", 음식점은 묻기만 · 경유지·목적지 2km 앞 곧 도착 안내 · 음성 해설(Pleos TTS) · 말로 대답 "들를래/괜찮아/이야기"(Pleos STT) · 위치 이야기) |
| 경유지 리뷰·"핫" | 경유지에서 주차하면 짧은 리뷰. 재방문 의사가 높은 곳에 "핫" 표시 | 동작 (리뷰 3종: 주차·웨이팅·재방문 의사) |
| 다시 탈 때 알림 | 경유지에서 다시 출발하면 "여행을 계속할까요?" | 동작 (시동 = 화면 켜짐으로 판단, 10초 무응답 시 계속) |
| 날씨·계절 반영 | 비 오는 날엔 실내 위주로 | 동작 (날씨 API 키가 없으면 기본 추천) |
| 경유지 3곳 이상 | 구간을 나눠 차례로 안내(NaviHelper 경유지 최대 2곳 제한) | 동작 (다음 경유지 1곳 + 목적지씩, P→D 로 다음 구간) |
| 내 지도 표시 | 이모지·색·무늬, 날짜, 횟수, 직접 체크, 지우기 | 동작 |

### 설정 (켜기·끄기)
| 묶음 | 항목 |
|---|---|
| 내 지도 | 자동 방문 기록(끄면 도착 시 기록할지 물어봄), 지도에 다녀온 곳 표시, 여러 번 간 곳 횟수 표시, 기본 표시, 방문 기록 전체 지우기 |
| 해설·소리 | 음성 해설, 말로 대답하기, 위치 이야기 자동 재생, 해설 볼륨(녹음 이야기에만 적용) |
| 화면 | 주간·야간(자동/주간/야간), 해설 글 보기, 주행 중 주변 갈 만한 곳 카드, 랜덤 다트 아이콘, 움직임 효과 |
| 추천 | 시작 질문, 날씨·계절 반영, "핫" 표시 |
| 리뷰·알림 | 경유지 리뷰, 다시 타면 "여행을 계속할까요?" |

설정 값은 `settings/AppSettings`에 저장됩니다. 1번이 만들고 다른 담당은 읽기만 합니다. 아직 기능이 없는 항목은 값만 저장되고 화면에 "준비 중"으로 표시됩니다.

### 코스 기준
팀 논의에서 정한 것입니다.

| 항목 | 결정 |
|---|---|
| 코스 개수 | 서로 다른 코스 여러 개 중 하나를 고름. 갈 곳이 적은 지역 3개, 많은 지역 최대 5개. 코스마다 장소 여러 곳 |
| 동선 | 항상 최적 동선이 우선 |
| 지역 범위 | 고른 도시 안 여러 구 + 가는 길 도시의 추천 코스. 최종 목적지는 처음 정한 도시 |
| 식당·카페 | 여행 시간에 따라 넣거나 뺌. 맛집·카페투어 테마는 그 자체가 중심 |
| 장소 수 | 여행 길이와 목적지 도착 시간을 보고 너무 늦기 전에 할 수 있는 만큼. 추천 테마를 먼저 여러 개 보여 주고 사용자가 골라 코스를 짬 |
| 마감 기준 | 장소 운영시간(도착 예상 시각에 문 닫는 곳은 뺌) |
| 1박2일 | 날짜별로 코스를 나눔. 숙소는 추천하지 않음 |
| 방문 기록 | 코스 중 주차(P)한 구는 모두 칸을 채움(자동 방문 기록을 끄면 매번 물어봄) |
| 가는 길 추천 | 기준은 지나가는 경로. 고속도로 구간은 최대한 줄이고 국도 위주. 고속도로에서는 IC 근처 3km 안 코스만 걸리는 시간과 함께 안내. 조수석에서 볼 수 있게 |

**아직 확인할 것**: 최적 동선의 이동시간을 무엇으로 구할지(2·3번), 고속도로·국도 구분과 IC 위치 데이터(2번), 조수석 표시와 주행 중 UI 제한의 충돌(1·2번), 운영시간이 없는 장소 처리(3번), 주차한 구 모두 기록하기 위한 `TripCoordinator` 경유지 단계(2번).

### 먼저 맞출 것 (공통 파일이라 바꾸면 팀 공유)
1. 코스·테마 카드 데이터 모양(`core/model/`) — 3번이 만들고 4번 시안대로 1번이 그림
2. 리뷰·방문 기록 칸 추가 — 1번이 DB, 2번이 저장 시점
3. 설정 저장소 — 1번이 만들고 다른 담당은 읽기만 (완료: `settings/AppSettings`)
4. 여행 상태(`TripCoordinator`)에 경유지 구간·리뷰 단계 추가 — 2번
